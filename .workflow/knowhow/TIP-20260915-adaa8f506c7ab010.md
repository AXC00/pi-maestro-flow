# 跨扩展 UI 所有权握手：查询事件 + 幂等重播

## 问题

单所有者协议只在 `session_start` 与配置变更时广播一次 `cockpit:ui-ownership`，后加载的订阅方（Flow / Teammate）会错过唯一一次广播：它们的 `cockpitOwns*` 标志保持 false，原生面板与 Cockpit 面板同时渲染，形成重影。把广播改为"重播"并不能覆盖所有加载顺序，因为订阅方根本不知道自己错过了什么。

## 做法

1. **订阅方主动查询**：owner 暴露一个无参数查询事件（`cockpit:ui-ownership-query`）。每个订阅方在注册事件监听后立即发一次 query，并在每个 `session_start` 边界再发一次作为兜底。
2. **owner 应答即重播**：owner 收到 query 就调用同一个 `publishUiOwnership()`（幂等广播当前所有权），而不是维护订阅表或补发历史。
3. **活动起点再重播**：owner 在 agent 活动起点（如 `teammate:started`）再广播一次，消除"订阅已建立但第一帧仍未收到应答"的残留窗口。
4. **默认保守**：订阅方在收到应答前保持本地默认值（不接管原生面板），因此最坏情况是短暂显示原生面，而不是双面叠加。

查询事件是纯读取语义，应答是幂等的全量广播，不会引入事件风暴；任何加载顺序下所有权都会在一个查询往返内收敛。
