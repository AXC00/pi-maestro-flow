Gateway tunnel credential lifecycle must fence both live MCP sessions and durable orphan generations.

When a tunnel bearer authenticates an MCP session, re-authenticating only later HTTP requests does not revoke an already-open SSE/notification transport. Durable pairing revoke and replacement must emit a bounded revocation event; the Gateway HTTP owner tracks the pairing identity on each session and closes matching transports. Daemon restart or provider-runtime loss cannot rely only on in-memory cleanup: before recovering a successor, revoke active gateway.tunnel records by canonical provider and profile instance across all old generations. This keeps rotation, revoke, and restart fail-closed without revoking a successor credential.
