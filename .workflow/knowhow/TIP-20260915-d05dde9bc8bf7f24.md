# 稳定 widget 挂载 + renderKey 门控

## 问题

`setWidget(key, () => ({ render }))` 每次调用都会替换工厂闭包，host 会把 widget 视为新组件并重新挂载。若更新触发源有 9+ 处（started / complete / 1s timer / locale / stall sweep …），每次重建都会触发全量重绘；与另一个 UI 所有者的 250ms tick 叠加后产生可见闪烁与重影。这类 churn 不能靠"更快地重建"解决，只能靠"尽可能不重建"。

## 做法

1. **只在安装态切换时调用 setWidget**：`未安装 → 安装` 与 `有 → 无` 两个转换才注册/卸载；运行期内容变化只更新闭包读取的可变状态。
2. **renderKey 门控**：把可见行的状态序列化成一个稳定 key（状态、activity、elapsed、名称等）。key 不变直接返回；key 变化也只调用 `requestRender()`，不重建工厂。
3. **事件爆发合并**：所有触发点改为"标脏 + 短防抖（~100ms）"，对齐另一个所有者的微任务闩，避免一帧内多次重绘。
4. **守卫不必要的定时器**：无 widget 上下文、被 Cockpit 持有、面板活跃或前台运行时不调度刷新，并清理会话结束时的未决 timer。
5. **原子容器替换**：需要重建内容时用 `clear() + addChild()` 一次性替换，避免残留子行。

参考实现来自 `pi-subagents` 的 fleet-status：注册一次稳定 widget，序列化状态变化才 requestRender。

## 证据

- `packages/pi-maestro-teammate/src/extension/index.ts:10806` — `agentWidgetRenderKey()` 序列化可见行状态；
- `packages/pi-maestro-teammate/src/extension/index.ts:10869` — key 不变时跳过重建/刷新；
- `packages/pi-cockpit/src/index.ts` — 250ms tick 与 `renderContentKey` 门控（tick-policy 测试覆盖）。
