## 场景

跨扩展共享终端表面（Cockpit/Flow/Teammate 通过 `cockpit:ui-ownership` 单所有者协议）的缺陷（重影/双面板/churn）属于**跨扩展竞态 + widget 重建**，只有在真实扩展代码被驱动时才暴露。仅对源码做正则断言的"测试"（如 `test/cockpit-ownership.test.ts` 断言源码里出现某段文本）在改动被删除后依然全绿，无法围栏。

## 做法：fake host 驱动真实扩展入口

- 入口形态：三个扩展的入口都是 `(pi: ExtensionAPI) => void`，ctx 由生命周期事件提供 → 只需伪造 `pi` 与 `ctx`，不必伪造宿主渲染器。
- `pi` 用 Proxy 自动补桩：显式实现 `events.on/emit`（同步总线）、`on`、`registerTool/Command/Shortcut/MessageRenderer`、`getActiveTools/setActiveTools/registerFlag`，其余属性返回 `() => undefined`。
- `ctx`：`hasUI: true`、`mode: "tui"`（`isTuiContext` 门控）、`sessionManager` 兜底、`isProjectTrusted: () => false`（阻断 MCP 初始化）。
- 动态 import **真实入口**（`await import("../src/index.ts")` 与跨包相对 URL），按不同加载顺序各起一个 host。
- 记录 `setWidget`/`setFooter` 调用，并用栈帧归因调用方：跳过 harness 自身文件帧，正则抓 `packages/(pi-[^/]+)/(.+?):(\d+)`，再把 `\` 归一化为 `/`，即可断言"谁挂载了什么"。

## 可执行断言形态（已落地）

1. 三种加载顺序下，Cockpit 挂载自己的面，而原生面（`teammate-agents`/`todo-panel`/`goal-panel`）零挂载。
2. 跨扩展往返被真实执行：Teammate 的 `alt+r` 处理器发 `cockpit:open-session-list`，由 Cockpit 监听器接手。
3. `session_start` **之后**加载的 Teammate 实例仍能收敛（query → 应答），覆盖 /reload 场景。
4. `teammate:started` 突发后 widget/footer 写入零增长（churn 与 ownership 重播都不得变成重挂载）。
5. 同一 correlationId 的重复 started 只渲染一行（重复行=可见重影），断言放在真实 widget factory 上：捕获 `setWidget(key, factory)`，用 fake tui(`{terminal:{columns,rows}, requestRender, invalidate}`) 调 `factory(tui, theme).render(width)` 后数行。
6. footer 归属：最后一次 `setFooter(+)` 必须属于 Cockpit，Flow 的 statusline 必须撤下。

## 陷阱（都是实际踩过的）

- **包名导入会被 Node 拒绝**：`import("pi-maestro-teammate/src/...")` 经 node_modules 符号链接解析后触发 `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`。跨包导入一律用相对 URL：`new URL("../../pi-maestro-teammate/src/extension/index.ts", import.meta.url).href`。
- **不要碰用户真实配置**：`PI_CODING_AGENT_DIR` 指向临时目录并写入确定性的 `cockpit.json`（enabled/hideNativeAgents 等），且在 import 之前设置（ESM 提升要求用动态 import）。
- **ownerless 生命周期事件会被丢弃**：Cockpit 绑定会话后 `admitProjection(undefined, …)` 判 stale；伪造的 `teammate:started` 必须带 `projection: { workspaceId, sessionId, sourceId, generation ≥ 1 }`，且 sessionId 与 fake `ctx.sessionManager.getSessionId()` 一致。
- **必须显式收尾**：测试结尾 fire `session_shutdown`，否则 Flow 侧定时器/服务会让测试进程挂住（suite 出现假超时）。
- 归因用的栈帧要跳过 harness 文件自身的帧，否则所有写入都会被归到测试文件（Windows 路径还要归一化分隔符，否则 `startsWith` 断言假失败）。

## 反证要求（否则等于没验证）

断言必须有牙齿：临时把生产侧的应答实现改成空实现（例如 Cockpit 的 `COCKPIT_UI_OWNERSHIP_QUERY_EVENT` 处理器），late-load 用例必须失败；恢复后必须通过。只"跑绿"不构成验证。
